# CodeJev Ground-Truth Benchmark Subsystem (Phase 14)

Welcome to the **CodeJev Benchmark & Accuracy Evaluation System**.

The purpose of this subsystem is to measure CodeJev's real-world precision, recall, F1 score, false-positive rate, localization accuracy, and severity agreement against manually verified ground-truth datasets.

---

## 1. Ground-Truth Principles

1. **Empirical Verification**: Ground truth expected findings are defined manually by human engineers, **NOT** generated by CodeJev itself.
2. **Positive & Negative Balance**: Contains both positive cases (known bugs / security vulnerabilities) and negative clean cases (safe code patterns to measure false positives).
3. **Exact & Overlap Localization**: Evaluates whether CodeJev pinpoints exact line numbers or overlapping line ranges.
4. **Offline & Self-Contained**: Runs 100% offline without requiring network access, external AI APIs, or cloud services.

---

## 2. Dataset JSON Format (`benchmarks/synthetic_cases.json`)

```json
{
  "id": "py-sec-sql-001",
  "language": "python",
  "category": "SECURITY",
  "is_positive": true,
  "files": {
    "db.py": "def get_user(user_id):\n    query = 'SELECT * FROM users WHERE id=' + user_id\n    cursor.execute(query)\n"
  },
  "expected_findings": [
    {
      "type": "SECURITY",
      "severity": "HIGH",
      "file": "db.py",
      "start_line": 3,
      "end_line": 3
    }
  ],
  "description": "Dynamic SQL string concatenation passed to cursor.execute()"
}
```

---

## 3. How to Run the Evaluation CLI

Run the benchmark evaluator from the repository root:

```bash
.venv/bin/python -m backend.benchmark
```

### Command Options

- `--dataset PATH`: Specify custom dataset file (default: `benchmarks/synthetic_cases.json`)
- `--output-dir PATH`: Directory where `evaluation.json` and `evaluation.md` are saved (default: `results/`)
- `--language python|javascript|typescript`: Filter evaluation to specific language
- `--category SECURITY|BUG|PERFORMANCE`: Filter evaluation to specific category
- `--threshold-precision FLOAT`: Optional minimum precision check (exits 1 if failed)
- `--threshold-recall FLOAT`: Optional minimum recall check (exits 1 if failed)

---

## 4. Evaluated Metrics

- **Precision**: `TP / (TP + FP)`
- **Recall**: `TP / (TP + FN)`
- **F1 Score**: `2 * Precision * Recall / (Precision + Recall)`
- **False-Positive Rate (FPR)**: `FP / (FP + TN)` (on clean negative cases)
- **Exact Line Accuracy**: Percentage of matched findings pointing to identical start/end line numbers.
- **Range Overlap Accuracy**: Percentage of matched findings overlapping expected line ranges.
- **Severity Agreement**: Percentage of matched findings with identical severity classifications.
